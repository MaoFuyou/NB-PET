# Contributing

Keep each change focused and document any change to an input contract or evaluation definition. Run `python3 -m unittest discover -s tests -v` before requesting review.

Use synthetic fixtures and minimal error excerpts. Do not include patient images, reports, identifiable case records, credentials, access tokens, private infrastructure details, or weights in issues, pull requests, or commits. If material could identify a participant or reveal a credential, contact the maintainer through an approved private channel instead.

Claims and scores added to the README should match a versioned, reviewed result, with the cohort, protocol, and aggregation rule documented. Publishing new assets, data access information, or weights requires approval separate from code review.
